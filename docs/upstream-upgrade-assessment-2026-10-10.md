## 本地版本与独立功能背景

本地仓库在 2026-06-28 以 `f07e4da7`（初始化项目代码）重新建立提交历史，没有与上游 rc.19 的共同 Git 祖先。线路相关代码在当天已经加入，后续持续独立迭代。

在已比较的 rc.12～rc.19 标签中，初始化代码的非前端部分与 rc.15 的差异最小。这只能作为代码相似性的线索，不能据此断言精确分叉版本，也不能用本地存在 rc.19 标签证明该版本已完整同步。实施前应补查 rc.16～rc.19 中仍有价值的缺失项。

目前本地已有的独立能力包括：

- 线路配置、线路选渠、线路价格及倍率、模型广场线路展示。
- API Key 线路管理及管理员管控、CSV 批量禁用密钥。
- 上游账号余额监控、定时查询和低余额邮件提醒。
- 历史消费日志修正与统计一致性处理。
- OpenAI 缓存写入计费、部分额度安全处理及 Codex 请求头透传修复。

消费汇总相关代码在本次评估时仍有未提交工作，应在后续升级开始前确认其最终版本。不能将上游更新直接覆盖到这些功能上。

## 建议升级的功能包

### 1. 计费、退款与统计一致性：优先核对和修复

- 流中断、上游显式失败和已产生用量的结算边界。
- 分组或线路在重试过程中变化时，使用正确价格结算，并在必要时补足预扣。
- 缓存读写、图片、工具搜索和多模态用量的归一化及重复计费问题。
- 条件倍率与时间规则正确匹配，并在管理员日志中展示命中规则。
- 充值、退款、兑换码精度和累计消耗的一致性。
- 日志统计、历史消费修正、月度汇总在价格及字段变化后的兼容性。
- 大额度钱包作为独立迁移，区分钱包累积额度与单请求额度边界。

主要来源：rc.20～rc.27、rc.30～rc.31、rc.37～rc.39、rc.42。

### 2. 请求稳定性与协议兼容：优先引入

- 响应头超时、可重放请求体、代理与每渠道传输配置。
- 客户端取消后的上游请求生命周期，尤其是 Bedrock。
- Chat、Responses、Claude、Gemini 的工具调用、图片、推理参数及用量保留。
- 转换警告和工具丢失策略，减少难以解释的兼容问题。
- zstd 请求解压、请求长度校验、multipart 请求头一致性。
- 静态资源不计入页面限流，减少首次加载误触发 429。
- Responses WebSocket 按实际客户端需求安排。

主要来源：rc.23～rc.25、rc.28、rc.31～rc.33、rc.38、rc.40～rc.43。

### 3. 模型与定价管理：主要功能升级

- 未定价模型筛选、模型发现与厂商管理。
- 模型/厂商批量操作与引用清理。
- 价格编辑并发保护和修改审计。
- 旧倍率转表达式草稿、有效价格预览和替换确认。
- 条件、按次、时段、图片及缓存价格的编辑和展示。
- 价格同步、表达式差异高亮、元数据批量同步。
- 模型目录及模型广场可见性、显示币种。

这部分直接改善“模型 × 线路 × 价格”的维护效率，应纳入主要升级范围。需要沿用本地线路价格展示，而不是只更新上游基础模型价格页面。

主要来源：rc.21～rc.22、rc.34、rc.36～rc.37、rc.39、rc.41。

### 4. 渠道配置与线路运营：主要功能升级

- New API、Sub2API、vLLM、SGLang 等渠道类型及所需协议。
- 统一渠道创建/编辑、模型发现、模型映射工作台与上游变更预览。
- 按用户/分组和正则条件进行参数覆盖。
- 按字段/路径透传、每渠道 HTTP 配置。
- 渠道测试只自动禁用模式及原生协议测试。
- 请求策略、重试决策、健康状态和响应模型不一致日志。
- 模型全天健康曲线；可进一步扩展到线路维度。

本地已有模型映射和上游模型变更检测基础，应比较能力差异。自动分组、会话亲和和重试仍必须遵守 API Key 的线路约束；健康策略不能隐式绕过固定线路。

主要来源：rc.22～rc.25、rc.35、rc.37～rc.39、rc.42。

### 5. 模型变体与推理参数：适配后引入

上游支持如 `model@effort:high`、`model@thinking:on` 的模型参数后缀，并提供规范化的变体计费名称。等价后缀组合可以匹配同一个价格，未配置变体价格时回退到基础模型。

这适合提供不同推理档位和线路价格，但需要同步处理：

- 原始模型、基础模型、映射后模型和计费模型的身份。
- API Key 模型限制、模型列表及线路匹配。
- 基础价格、变体价格与线路价格之间的优先级。

## 已核对的关键移植约束

### 阶梯计费快照不能丢失线路倍率

本地 `relay/helper/price.go` 的 `modelPriceHelperTiered` 将“分组倍率 × 线路倍率”写入 `BillingSnapshot.GroupRatio`。

上游 rc.43 的 `service/tiered_settle.go` 包含重试前按最终分组刷新快照的逻辑。直接照搬可能用纯分组倍率覆盖本地的组合倍率，导致线路价格丢失。

移植时必须明确分组和线路倍率的来源，按最终选择计算有效倍率，并核对更高价格重试前的预扣补足。回归场景应包含跨渠道/分组重试、固定线路、线路回落、免费转付费和表达式结算。

### 请求体重放要创建独立 Reader

本地 `relay/channel/api_request.go` 的任务请求 `GetBody` 闭包返回同一个 Reader 的包装，不等同于从头重放；普通请求路径也不能只依赖 `http.NewRequest` 自动识别请求体。

上游通过可重放请求体创建新 Reader，无法安全重放时避免错误重试。移植应覆盖普通 JSON、存储型请求体和 multipart 等实际路径。

### 数据库升级需与本地扩展模型一起验证

本地额度转换仍含 int32 边界。上游大额度钱包扩展区分单请求和钱包额度，并检查钱包字段类型，不能简单全局替换所有限制。

涉及驱动、字段、旧唯一约束和 AutoMigrate 的改动，应保持 SQLite、MySQL、PostgreSQL 兼容，同时覆盖线路、余额监控、历史修正和月度汇总。rc.29/rc.30 中依赖上游此前改动的修复，需要先确认本地是否适用。

### 协议和前端结构差异需适配

本地还使用独立的 `web/default`、`web/classic` 主题目录；此次查阅的上游 rc.43 前端位于 `web/src`。协议转换模块也经历了整理。前端功能应迁移到本地对应模块，避免直接按上游文件路径覆盖。

前端文本按本地 i18n 约定维护全部支持语言。后端多语言升级要纳入线路、余额监控、历史修正和消费汇总的新增错误及通知。

### 已有功能按差异补齐

已看到本地存在缓存写入计费、Codex 请求头透传、额度安全转换、任务状态 CAS、防重复退款的部分保护，以及模型映射/上游检测基础。

这些不能直接标记为“全部缺失”或“已经完全等价”。应比较输入、计费语义、调用路径和已有回归覆盖，再决定保留、补差或替换。
